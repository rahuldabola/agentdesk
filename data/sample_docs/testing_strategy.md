# Testing Strategy

## Test Pyramid

Most tests are unit tests that run in milliseconds without network or disk. Integration tests
exercise a service against real dependencies started in containers. End-to-end tests are few,
cover only critical user journeys such as sign-up and checkout, and run against staging.

## Coverage

New code in Tier 1 services must keep line coverage at or above 80%. Coverage is a floor, not a
goal: a test that executes a line without asserting on its behaviour adds nothing.

## Flaky Tests

A test that fails and then passes on retry without a code change is flaky. Flaky tests are
quarantined automatically after three flaky failures in a week: they keep running but no longer
block merges, and a ticket is filed with the owning team. A quarantined test that is not fixed
within 14 days is deleted.

## Test Data

Tests never use production data. Fixtures are generated by factories, and integration tests use
the synthetic data generator for realistic volumes.

## Performance Tests

Changes to Tier 1 request paths run a load test in staging before release. A regression of more
than 10% in p99 latency blocks the release until it is explained.
